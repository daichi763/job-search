# AI検索（新方式）— フェーズ1：検索エンジン本体と評価コマンド

求人DB（hub）の**全求人を母集団**として、求職者に合う求人を探す新しいAI検索です。
媒体に毎回ログインする旧方式（worker）とは別に動きます。フェーズ1は**評価コマンドだけ**なので、稼働中の画面やAI検索には影響しません。

## 仕組み（4段階）

| 段階 | やること | モデル |
|---|---|---|
| 1. 理解 | 要望と書類の経歴から「探し方（切り口）」を3〜6個作る。**王道**（経験そのまま）・**発展**（キャリアアップ）・**意外**（人の手では思いつきにくい隣接領域） | 優秀モデル |
| 2. 絞り込み | 画面の確定条件（勤務地・年齢・年収・雇用形態・働き方・学歴・性別・紹介済みの除外）で**全求人**から母集団を作り、切り口のキーワードで関連の強い順に並べる | なし（DBのみ・数秒） |
| 3. 一次審査 | 関連の強い求人（標準2,000件／徹底8,000件／全件）を安価なモデルで5段階評価 | 高速モデル |
| 4. 精査 | 有望な求人（最大120件）を**求人票の全文**で審査。必須要件を1つずつ「○満たす／×満たさない／？不明」で判定し、根拠を付ける | 優秀モデル（「最高精度」なら最上位モデル） |

### 応募条件を満たさない求人が高得点になる問題の対策
- 以前は応募条件の**先頭300字**しかAIに渡していなかった。今回からは**全文**（最大3,500字）を渡す
- 必須要件ごとの判定結果から、**最終点はプログラムで決める**（AIの点数をそのまま使わない）
  - 必須要件に「×」が1つでもある → **55点が上限**。提案には入れず「参考（内容は合うが要件不足）」に回す
  - 書類があるのに必須要件を確認できない（？）→ **84点が上限**（応募前の確認事項に表示）
- 学歴・性別の条件は、AIではなくプログラムで機械的に判定する

### 提案の幅
- 一次審査の対象は、切り口ごとの上位を均等に入れ、さらに職種ごとに少しずつ入れる（キーワードに当たらない職種の取りこぼしを防ぐ）
- 精査の対象も切り口ごとに枠を取る（似た求人だけで枠が埋まらないように）
- 提案の上位2割までは、王道以外（発展・意外）で75点以上の求人を入れる
- 同じ会社の同じ募集（媒体違いなど）は1件にまとめる

## モデルの設定（`hub/.env`）

未設定なら次の既定値を使います。使えないモデル（契約していない等）は自動で次の候補に切り替えます。

```bash
HUB_AI_MODEL_SMART=gpt-6.1-sol       # 理解・書類の読み取り・精査
HUB_AI_MODEL_TOP=gpt-6-astra         # 「最高精度」を選んだときの精査
HUB_AI_MODEL_FAST=gpt-6-luna         # 一次審査（大量）
HUB_AI_FALLBACK_MODELS=gpt-5.5,gpt-5.2,gpt-5        # 優秀モデルが使えないときの候補（順番に試す）
HUB_AI_FALLBACK_FAST_MODELS=gpt-5-mini,gpt-5-nano   # 高速モデルが使えないときの候補
# APIキー・接続先は worker/.env の OPENAI_API_KEY / OPENAI_BASE_URL をそのまま使う
#   別のキーにしたい場合だけ HUB_AI_API_KEY / HUB_AI_BASE_URL を指定

# 件数などの調整（任意）
HUB_AI_SCREEN_STANDARD=2000   # 標準: 一次審査の件数
HUB_AI_SCREEN_DEEP=8000       # 徹底: 一次審査の件数
HUB_AI_DEEP_MAX=120           # 精査の最大件数
HUB_AI_CAP_UNMET=55           # 必須要件を満たさない求人の上限点
HUB_AI_CAP_UNKNOWN=84         # 必須要件を確認できない求人の上限点
HUB_AI_MIN_SCORE=60           # 提案する最低点
HUB_AI_CONCURRENCY=8          # 同時に送る数
```

### 費用を抑える仕組み（2026-10 改訂）
初回の実データ評価（書類なし・提案20件）で約145円かかり、その大半（約85%）が「精査」でした。精度を保ったまま次の4点を変えています。

| 変更 | 内容 | 効果 |
|---|---|---|
| 精査を「判定」と「推薦文」に分割 | 精査では必須要件の○×？と点数だけを出し、推薦文・懸念・確認事項は**提案に残った求人だけ**書く | 精査の出力が半分以下に |
| 精査を少しずつ進めて途中で止める | 有望な順に精査し、80点以上の候補が「提案件数＋25%」集まったら終了 | 精査件数が 80件 → 30〜50件程度に |
| 一次審査の送る量を削減 | 求人1件の要約を短く（応募条件は必須部分だけ）、経歴は要点だけ、1回25件ずつ | 一次審査の入力が約4割減 |
| 精査の仕事内容を2,000字まで | 応募条件は従来どおり全文 | 精査の入力が約1〜2割減 |

**見込み: 同じ条件で約50〜70円（以前の約半分以下）**。実行後に段階別の費用を表示するので、実際の値を確認できます。

さらに抑えたい場合は費用モードで調整できます（`--cost=economy` または `hub/.env` の `HUB_AI_COST_MODE`）。

| 費用モード | 一次審査 | 精査（最大） | 判定の深さ | 目安 |
|---|---|---|---|---|
| economy | 1,200件 | 提案件数×2.5 | 浅め | 約30〜40円 |
| standard（既定） | 2,000件 | 提案件数×4 | 標準 | 約50〜70円 |
| quality | 3,000件 | 提案件数×6 | 深め | 約100〜150円 |

1回あたりの上限も決められます: `HUB_AI_MAX_USD=0.5`（上限の85%に達したら精査を打ち切る）。
推薦文だけ別のモデルにすることもできます: `HUB_AI_MODEL_WRITE=gpt-6-luna`（さらに約10円下がるが、文章の質は下がる可能性あり）。

## 評価コマンド（VPS）

```bash
cd /home/ubuntu/webapp/hub

# まず母集団の件数だけ確認（AIを呼ばない・無料）
node --no-warnings bin/ai-search.js --locations=東京都 --age=32 --education=大卒 --salaryMin=500 --dry

# 実行（書類は複数指定できる。種類は resume=履歴書 / cv=職務経歴書 / other）
node --no-warnings bin/ai-search.js \
  --text="顧客を長く支援する仕事がしたい。転勤は避けたい" \
  --doc=cv:/home/ubuntu/test/職務経歴書.pdf --doc=resume:/home/ubuntu/test/履歴書.pdf --names="山田 太郎" \
  --locations=東京都,神奈川県 --age=32 --education=大卒 --salaryMin=500 --features=weekend_off --top=20

# 手動検索で選んだ求人だけを審査（一次審査を飛ばして全件を精査）
node --no-warnings bin/ai-search.js --text="..." --doc=cv:... --jobs=circus:12345,hitolink:678

# 精度・件数の切り替え
#   --depth=deep        一次審査を8,000件に
#   --depth=all         条件に合う全求人を一次審査（件数が多いと時間と費用がかかる）
#   --precision=top     精査を最上位モデルで
```

| オプション | 内容 |
|---|---|
| `--text` / `--memo` | 要望・担当者メモ |
| `--doc=種類:パス` | 書類のPDF（複数可） |
| `--names` | 求職者の氏名（書類から伏せるため。AIには送らない） |
| `--locations` `--age` `--gender` `--education` `--salaryMin`（万円） | 確定条件 |
| `--employment` `--category` `--features` `--source` | 雇用形態・職種・働き方・媒体（カンマで複数） |
| `--exclude=媒体:ID,...` | 紹介済みなど、除外する求人 |
| `--jobs=媒体:ID,...` | この求人だけを審査 |
| `--conditions=条件.json` | 条件をまとめてJSONで渡す |
| `--out=結果.json` | 結果の保存先（既定は `hub/data/ai-results/`） |

結果には、提案ごとの**必須要件の判定（○×？と根拠）**、推薦理由、懸念点、応募前の確認事項、AIの元の点数と上限処理の有無が入ります。

### 個人情報の扱い
- PDFは読み取ったあと保存しません
- 氏名・住所・電話・メール・生年月日は、AIに送る前に伏せ字にします（`--names` で渡した氏名も本文から消します）
- 結果ファイルには、伏せ字にした経歴の要約だけが残ります

## 試験データでの確認結果（開発環境・gpt-5 / gpt-5-nano）

| 確認したこと | 結果 |
|---|---|
| 「顧客を長く支援したい」営業8年の人 | 改善前は法人営業ばかり提案（志向に合うカスタマーサクセス求人が1件も精査に残らなかった）→ 改善後は**カスタマーサクセスが上位**に、既存深耕型の営業がそれに続く形になった |
| 法人営業1年の人に、厳しい要件の求人16件を審査 | 「法人営業3年以上」「マネジメント5年以上」「簿記2級」などを満たさない13件は、AIの点数が70点でも**すべて55点以下**になり提案から外れた。提案は要件を満たす3件だけ |
| 個人情報 | 氏名・住所・電話・メール・生年月日が伏せ字になることを確認 |
